# Smart Clip 转化审计

审计时间：2026-08-09（Asia/Shanghai）

目标漏斗：访问首页 -> 开始使用 -> 注册成功 -> 首次渲染完成 -> 下载

方法：生产站真实点击、桌面/移动端检查、注册/渲染/支付源码与现有产品演示交叉验证。使用 `conversion-optimization` 的漏斗、PIE、假设、实验和停止条件框架。

## 决策摘要

**当前不具备导流条件，也不应先做 A/B 测试。** 英中首页“打开渲染工作台”链接在正常客户端点击后都会稳定进入 `/_serverFn/login` 404，主漏斗在第一步即中断。即使用户从价格页或直接 URL 绕过该问题，注册仍要求同意明确标为占位的服务条款与隐私政策。

最先要做的是修复确定性缺陷、校准承诺、补齐事件；这些不是实验变量。完成后至少记录一个完整周周期的原始数量，再决定是否有足够流量进行对照实验。受控 Beta 流量较低时，优先发布明显修复并结合隐私安全的可用性测试，不用小样本制造“显著提升”。

## 当前漏斗

| 阶段 | 当前用户路径 | 事件 | 状态 |
| --- | --- | --- | --- |
| 到达 | `/` 或 `/zh` | `page_view` | 已有，交接与本次网络请求均验证 |
| 点击主 CTA | 首页 Link -> `/app/render` | `cta_click` | 事件缺失；英中页面均稳定进入 404 |
| 开始注册 | 用户必须回退，或从价格页/直接 URL 到 `/register` | `sign_up_start` | 缺失 |
| 注册成功 | 表单提交；可能进入验证邮件状态，否则导航到 `/app` | `sign_up` | 缺失；不继续到原本承诺的渲染页 |
| 创建渲染 | 在 `/app/render` 填标题、MP4、语言和样式 | `render_start` | 功能存在，事件缺失 |
| 渲染完成 | 轮询/agent 把任务首次更新为 `completed` | `render_complete` | 功能与演示存在，事件缺失 |
| 下载 | GET `/api/render-outputs/<job-id>` | `result_download` | 功能存在，事件缺失 |
| 购买 | 公开 Pro 仍为 coming soon/waitlist | `purchase` | 购买入口 dormant；事件缺失 |

当前无法计算 CTA 点击率、注册成功率、首次渲染完成率、下载率或付费率。任何数值目标都必须等事件上线并积累基线后再设定。

## 关键发现

### P0 — CONV-01：主 CTA 的真实点击路径是 404

**复现**

1. 在无登录 Chromium 打开 `/` 或 `/zh`。
2. 点击首屏 `Open render workspace` / `打开渲染工作台`。
3. 英中页面的最终 URL 均为 `/_serverFn/login`，页面标题为 `Page not found — Smart Clip`。较早捕获的 `/zh/login` 是最终客户端重定向完成前的中间状态。

直接地址栏访问 `/app/render` 则正确 `307` 到 `/login`，说明问题只发生在客户端路由调用受保护 loader/server function 时。首页、桌面导航、移动菜单和页脚复用了同一目标，因此主站的大部分“开始使用”入口都受影响。

**修改方向**

- 修复 server function 重定向的客户端处理，或让匿名营销 CTA 显式进入注册/登录路由并携带经过校验的 `next=/app/render`。
- 登录用户继续直接进入渲染页；匿名用户 CTA 文案应说明真实下一步，例如“开始免费 Beta”，不能承诺立即打开工作台却展示登录或 404。

生产代码把 `loggedIn` 传给 `SiteNav`，但组件没有使用该值，仍把所有人固定指向 `/app/render`（`src/components/marketing/site-nav.tsx:11`、`:23`）。

**验收**

- 英中、桌面和移动端所有 CTA 点击均无 4xx。
- 匿名用户完成注册/登录后回到相同语言的 `/app/render`。
- `next` 只允许站内白名单路径，不能形成开放重定向。

### P0 — CONV-02：注册要求同意未定稿的占位法律文本

注册按钮只有勾选条款后才可提交，但 `/terms` 和 `/privacy` 明确写着“不是最终法律文本，公开上线前必须完成确认”。这既是信任中断，也是推广发布门槛。

法律内容需要业务/法律负责人提供；工程侧不应自动生成并冒充正式文本。在定稿前应暂停外部导流，必要时关闭公开注册。

### P0 — CONV-03：首页证据位是 404 占位图和内部说明

用户在首屏后看到的是“请替换图片槽位”、两个文件路径和 404 图片，而不是成片证据。仓库已经有 20 秒产品演示、77 秒真实浏览器流程和经过合成账号录制的完成/下载状态，应优先从这些真实素材制作首页证据，而不是添加虚构评价。

### P0 — CONV-04：产品承诺相互冲突

- 首页示例显示 `184 MB`，真实上传上限是 100 MB。
- 注册文案承诺把“第一条长视频变成 clip batch/可发布片段”，但输入限制和输出定义没有在营销页解释。
- 价格页把 AI 精选片段、9:16、私有项目存储列入免费 Beta；首页把精彩片段、画幅、私有媒体等放在 Pro 即将上线区。
- 状态页的“刚刚更新/全部正常”是静态文案。

推广前必须形成一份“当前可用 / 受控 Beta / Pro 计划”能力矩阵，并让首页、价格、注册、演示和事件命名使用同一版本。

### P1 — CONV-05：注册前后承诺不连续

- 首页说“打开渲染工作台”，匿名用户即使没有 404，也先看到“欢迎回来”的登录页，而不是注册入口。
- 从登录进入注册后，成功路径导航到 `/app`；没有保留最初的 `/app/render` 目标。
- 开启邮箱验证时，用户进入“已发送”状态，后续首次渲染路径没有可测的连续上下文。

应保留语言、可信的站内 return target 和渠道归因；注册/验证/登录成功后直接进入首个渲染任务，而不是让新用户重新寻找入口。

本次生产 loader 显示没有社交登录、Turnstile 或邮件验证，注册表单在填写合法姓名/邮箱/密码并勾选条款后可提交。审计没有创建生产账号，因此不能把注册成功或后续生产渲染记为已验证。

### P1 — CONV-06：页面很长，但末尾没有可点击 CTA

移动首页约 5,466-6,108px 高。首屏后最末 CTA 区只有 `PRO · COMING SOON` 徽章，没有按钮；移动导航 CTA 又藏在菜单中。滚动到价值说明末尾的用户缺少自然下一步。

在承诺校准后，应在真实成品证据和页面末尾各放一个相同主目标的 CTA，匿名/登录状态使用一致规则。

### P1 — CONV-07：价格页是孤立页面

价格页本身的注册 CTA 可用，但首页、主导航和页脚不链接它，sitemap 也不收录。用户无法在“开始使用”前自然确认免费 Beta、信用卡要求和 Pro 状态。

### P1 — CONV-08：渲染提交失败仍向用户返回成功

`createRenderJobFn` 在对象上传或渲染后端提交抛错时，会把任务写成 `failed`，但随后仍返回 `{ ok: true }`（`src/features/render-jobs/actions.ts:52`、`:76`、`:82`）。前端据此显示“任务已提交”成功提示并清空标题和文件（`src/routes/{-$locale}/app/render.tsx:190`、`:195`），之后列表同步才会暴露失败状态。

这会误导首次使用者，也会让“服务端成功创建并接受任务”这一 `render_start` 定义无法落地。应明确区分“记录已创建”“源文件已保存”和“任务已被渲染端接受”，失败时返回可恢复错误且不要弹成功提示；只有达到选定的权威状态后才上报一次 `render_start`。

### P1 — CONV-09：漏斗事件与跨阶段归因缺失

除 `page_view` 外，没有可靠方式区分“页面有人看”与“用户完成注册/渲染/下载”。在此状态下投放或集中发布无法归因，也无法判断修复是否有效。

源码没有显式的 `utm_*` 读取、持久化或账户/任务关联。即使 GA4 能识别落地会话的活动参数，目前也没有经验证的方式把渠道与服务端注册、渲染、下载事实对应起来；渠道级下游转化率仍不可用。

## 页面改动建议

### 首页

- 匿名主 CTA 使用真实注册目的地，登录用户进入渲染；所有位置共享同一状态逻辑和事件 `cta_id`。
- 删除内部占位说明，展示真实源素材和成片，或嵌入短版产品演示。
- 把当前可用工作流放在主叙事，Pro 计划缩短并明确“不可用”；不要让未来功能盖过现在能完成的任务。
- 修正 184 MB 示例，明确 MP4/100 MB 约束。
- 页面末尾提供真正可点击的主 CTA。
- 不直接公开仓库视频路径；先把已验收演示发布为稳定资源并确认样例媒体的外部分发许可。

> 2026-08-10 处理结果：公开演示已改为只用 FFmpeg 图形、文字和模拟数据生成，不再读取上述样例媒体；稳定资源、字幕、静帧与溯源记录已放入 `public/product-demo/` 和 `video/product-demo/review-packet.md`。

### 注册页

- 条款/隐私定稿后再导流。
- 从已验证的站内 `next` 参数说明注册后会进入渲染，而不是泛化承诺“clip batch”。
- 保留当前简短表单、明确密码限制和可恢复错误；不要增加营销字段。
- 邮箱验证开启时记录验证发送与最终注册确认的区别，`sign_up` 只以服务端账户事实触发。

### 首次渲染

- 注册/登录后直接打开渲染表单并保留语言。
- 创建任务失败时继续展示可操作原因；成功创建后才触发 `render_start`。
- `render_complete` 必须绑定第一次状态跃迁，轮询刷新不能重复上报。
- 下载 API 在认证和对象存在检查通过后触发 `result_download`，不得发送文件名、标题或邮箱。

### 价格页

- 只展示经过确认的免费能力与限制；Pro 计划价格和功能继续明确为计划值，不与可购买状态混淆。
- 从首页导航/页脚提供入口，并保持 CTA 与首页匿名路径一致。

## GA4 实施契约

| 事件 | 权威触发点 | 允许参数示例 | 幂等/隐私要求 |
| --- | --- | --- | --- |
| `cta_click` | 用户点击营销主 CTA | `cta_id`, `placement`, `locale`, `destination` | 不含文本输入或用户标识；一次点击一次事件 |
| `sign_up_start` | 注册表单首次有效交互或首次提交 | `locale`, `method` | 每次表单会话一次；不含邮箱/姓名 |
| `sign_up` | 服务端确认账号创建成功 | `method`, `locale` | 以账户创建事实幂等；不发送邮箱/姓名 |
| `render_start` | 服务端成功创建并接受渲染任务 | `locale`, `animation_id`, `translation_language` | 以 job ID 在服务端去重；不发送标题/文件名 |
| `render_complete` | job 首次从非完成态变为 `completed` | `animation_id`, `translation_language` | 以 job ID + 事件类型唯一；轮询不得重复 |
| `result_download` | 已认证用户成功请求存在的输出 | 可选 `first_download` | 不发送对象 key/文件名；明确统计每次还是首次下载 |
| `purchase` | Stripe webhook 确认已付款事实 | GA4 标准金额/币种/transaction_id | 使用 Stripe event/payment ID 幂等；公开销售启用时才上线 |

外部链接继续使用：

`https://dve2.com/zh?utm_source=<platform>&utm_medium=<format>&utm_campaign=smart_clip_launch&utm_content=<asset>`

参数使用稳定的小写英文/下划线。服务端事实若需要归因，应在不保存 PII 的前提下设计 client/session 与 UTM 关联；不能把邮箱、姓名、原始视频名或标题写入 GA4。

## 验证与实验顺序

### 第 0 阶段：确定性修复

完成 CTA、法律、占位图、能力矩阵和事件。使用合成账号跑英中、桌面和移动端完整流程，确认每个事件恰好出现一次。这个阶段不报告转化提升。

### 第 1 阶段：建立基线

- 至少覆盖一个完整周周期；流量很低时延长并只报告原始数量。
- 每周记录：landing sessions、`cta_click`、`sign_up_start`、`sign_up`、`render_start`、`render_complete`、首次 `result_download`。
- 对客户端事件与服务端事实做对账；任何重复、漏报或 PII 都阻止实验开始。

### 第 2 阶段：按顺序测试

| 假设 | 变体 | 主指标 | 保护指标 |
| --- | --- | --- | --- |
| H1：明确“开始免费 Beta”并直达注册，会减少入口误解 | 现有能力导向 CTA vs 校准后的 CTA | `sign_up / landing sessions` | CTA 404=0、注册错误率 |
| H2：真实 20 秒演示比静态说明更能建立信任 | 真实演示 vs 真实前后对比图 | `cta_click / landing sessions`，并观察 `sign_up` | 页面加载、移动端可读性 |
| H3：把未来 Pro 内容压缩到当前能力之后，会减少认知冲突 | 当前长 Pro 区 vs 简化计划区 | `sign_up / landing sessions` | 价格页访问、候补提交 |
| H4：注册后直接进入渲染可提高首次成功 | `/app` 中转 vs `/app/render` | `render_complete / sign_up` | 渲染失败率、支持反馈 |

每次只测试一个主要变量。实验开始前根据真实基线和最小可接受效果计算样本量，使用预先声明的统计方法；至少覆盖完整周周期，不因中途波动提前宣告赢家。

## 停止条件

立即停止或回滚某个变体：

- 任一 CTA 出现 4xx/5xx、开放重定向、语言丢失或无法继续注册。
- 注册条款链接不可用、法律状态回退为占位，或产生未授权注册。
- 渲染成功率、错误恢复、移动端可用性出现预先定义的实质性退化。
- 事件重复、服务端事实对账失败，或任何事件包含 PII/原始媒体信息。

停止并判定“证据不足”：

- 未达到预先计算样本量或未覆盖完整周周期。
- 渠道结构在实验中途发生重大变化且无法分层解释。
- 只有页面访问变化，没有注册/首次渲染事实支持。

本文件是只读审计结果。本轮未修改页面、认证、渲染或统计代码，也未部署。
